# 작명 데이터 구축 To-Do

## 목표

작명 서비스를 단순 이름 추천이 아니라, 등록 가능 여부와 성명학 계산 근거를 함께 제시하는 서비스로 확장한다.

## 1. 공식 인명용 한자 데이터

- [ ] 대법원/법원 전자가족관계등록시스템 인명용 한자표 원본 확보
- [ ] 국가법령정보센터 「가족관계의 등록 등에 관한 규칙」 별표 원본 확보
- [ ] 한자, 허용 음, 유니코드, 등록 가능 여부, 최신 개정일 추출
- [ ] PDF/별표 파싱 스크립트 작성
- [ ] `naming_hanja` 테이블 설계
- [ ] `naming_hanja_readings` 테이블 설계
- [ ] 공식 데이터 출처와 기준일을 `source`, `version`, `effective_date`로 저장

## 2. 한자 사전 보강 데이터

- [ ] Unicode Unihan Database 다운로드 방식 확정
- [ ] `kKorean`, `kHangul`, `kDefinition`, `kTotalStrokes`, `kRSKorean`, `kRSUnicode` 필드 검토
- [ ] 한자별 뜻, 대표 음/훈, 총획수, 부수, 강희자전 획수 추출
- [ ] 인명용 한자 목록과 Unihan 데이터를 매칭
- [ ] `naming_hanja_meanings` 테이블 설계
- [ ] `naming_hanja_strokes` 테이블 설계

## 3. 성명학 계산 규칙 데이터

- [ ] 음오행 기준 확정
- [ ] 자음별 음오행 매핑 데이터 작성
- [ ] 자원오행 기준 확정
- [ ] 한자별 자원오행 데이터 작성 또는 검증
- [ ] 원격, 형격, 이격, 정격 계산 방식 확정
- [ ] 81수리 길흉표 작성
- [ ] 불용한자 목록 작성
- [ ] 성씨별 획수/오행 데이터 작성
- [ ] `naming_phonetic_elements` 테이블 설계
- [ ] `naming_hanja_elements` 테이블 설계
- [ ] `naming_81_numbers` 테이블 설계
- [ ] `naming_forbidden_hanja` 테이블 설계
- [ ] 유파별 차이를 기록할 수 있도록 `method`, `source`, `version` 컬럼 추가

## 4. 이름 후보 생성 데이터

- [ ] 이름 음절 후보 데이터 작성
- [ ] 성별/중성 이름 태그 설계
- [ ] 밝은, 단정한, 지적인, 부드러운 등 이미지 태그 설계
- [ ] 한글 발음상 어색한 조합 필터 작성
- [ ] 성씨별 발음 충돌 필터 작성
- [ ] 너무 흔한 이름/너무 낯선 이름 필터 기준 작성
- [ ] `naming_syllables` 테이블 설계
- [ ] `naming_candidate_rules` 테이블 설계
- [ ] `naming_candidate_scores` 테이블 설계

## 5. 인기 이름/트렌드 데이터

- [ ] 연도별 인기 이름 데이터 원천 조사
- [ ] 성별 인기 이름 데이터 원천 조사
- [ ] 이름 음절 빈도 데이터 원천 조사
- [ ] 성씨별 조합 빈도 데이터 사용 가능 여부 검토
- [ ] 개인정보 및 라이선스 이슈 검토
- [ ] `naming_name_trends` 테이블 설계
- [ ] 트렌드 데이터 업데이트 주기 정의

## 6. 작명 점수 로직

- [ ] 등록 가능 점수
- [ ] 사주 보완 오행 점수
- [ ] 음오행 점수
- [ ] 자원오행 점수
- [ ] 획수/수리 점수
- [ ] 뜻/이미지 점수
- [ ] 발음 조화 점수
- [ ] 트렌드 점수
- [ ] 불용/주의 감점
- [ ] 최종 점수 가중치 설계
- [ ] 점수 산출 로그 저장 구조 설계

## 7. 프롬프트/리포트 출력

- [ ] 작명 결과용 GPT 프롬프트 템플릿 작성
- [ ] 이름 후보별 한자, 뜻, 오행, 획수, 점수 근거를 구조화
- [ ] HTML 리포트 출력 형식 정의
- [ ] 사용자가 입력한 선호 이미지와 피하고 싶은 글자를 프롬프트에 반영
- [ ] 등록 가능 여부와 성명학 해석을 분리해서 설명
- [ ] 공식 등록 가능 여부는 단정하고, 성명학 해석은 기준/유파를 표시

## 8. 데이터 업데이트 주기

- [ ] 인명용 한자표: 법원/대법원 개정 여부 분기별 확인
- [ ] Unihan Database: Unicode 버전 릴리스 시 확인
- [ ] 성명학 규칙 seed: 서비스 운영 중 필요 시 개정
- [ ] 인기 이름/트렌드: 연 1회 또는 반기 1회 업데이트
- [ ] 불용한자/주의 문구: 운영 피드백에 따라 수시 개선

## 9. 우선순위

1. 공식 인명용 한자표 확보 및 DB화
2. Unihan으로 뜻/획수/독음 보강
3. 음오행, 자원오행, 81수리, 불용한자 seed 작성
4. 작명 후보 생성 로직 구현
5. 사주 보완 오행과 작명 점수 연결
6. GPT 프롬프트와 HTML 리포트 출력
7. 인기 이름/트렌드 데이터 추가
