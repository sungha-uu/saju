# 사주/운세 대시보드 개발 문서

## 1. 프로젝트 개요

이 프로젝트는 사용자가 재미삼아 사주팔자, 궁합, 오늘의 운세, 작명 결과를 확인할 수 있는 웹 기반 대시보드 서비스다. 관상, 손금, 타로, 꿈해몽 등은 확장 기능으로 남겨두고, 1차 개발에서는 생년월일시와 기본 프로필을 기반으로 한 운세 콘텐츠 생성 경험을 완성한다.

서비스의 핵심은 "전문 점술 서비스"가 아니라 "가볍고 몰입감 있는 엔터테인먼트 콘텐츠"다. 모든 결과 화면에는 과도한 단정, 건강/투자/법률 판단, 운명 확정식 표현을 피하고, 참고용/재미용 안내를 명확히 포함한다.

## 2. 목표

### 2.1 1차 목표

- 사용자가 생년월일시, 성별, 양력/음력 여부를 입력해 사주팔자 분석을 받을 수 있다.
- 두 사람의 기본 정보를 입력해 궁합 결과를 받을 수 있다.
- 오늘 날짜 기준의 오늘의 운세를 카드 형태로 확인할 수 있다.
- 성씨, 성별, 선호 이미지/뜻/음절 조건을 입력해 작명 후보를 받을 수 있다.
- 대시보드에서 최근 조회 결과와 즐겨찾기 결과를 다시 열람할 수 있다.
- AI가 생성하는 해석은 구조화된 JSON 또는 마크다운 형식으로 저장/표시할 수 있다.

### 2.2 추후 목표

- 관상: 얼굴 이미지 업로드 기반 엔터테인먼트 해석
- 손금: 손바닥 이미지 업로드 기반 엔터테인먼트 해석
- 타로, 꿈해몽, 별자리 운세, 띠별 운세
- 사용자 계정, 결제, 리포트 PDF 저장, 공유 이미지 생성
- 관리자용 프롬프트/콘텐츠 템플릿 관리

## 3. 타깃 사용자

- 사주/운세를 가볍게 즐기고 싶은 일반 사용자
- 커플 궁합, 친구 궁합을 재미로 확인하고 싶은 사용자
- 아이 이름, 닉네임, 브랜드명 후보를 영감 차원에서 받아보고 싶은 사용자
- 복잡한 명리학 용어보다 쉬운 설명과 보기 좋은 결과 화면을 원하는 사용자

## 4. 핵심 원칙

- 결과는 단정하지 않는다. "반드시", "무조건", "인생이 망한다" 같은 표현을 금지한다.
- 건강, 질병, 투자, 법률, 임신, 사망, 사고 예측은 제공하지 않는다.
- 개인 정보 입력은 최소화하고, 저장 여부를 사용자가 선택할 수 있게 한다.
- AI 결과는 매번 말투가 달라도 화면 구조는 일관되어야 한다.
- 사주 명식 계산처럼 규칙 기반으로 가능한 영역은 코드로 계산하고, AI는 해석/문장화에 집중한다.
- 모바일에서도 한 손으로 입력하고 결과를 읽기 쉬워야 한다.

## 5. MVP 기능 범위

### 5.1 공통 대시보드

주요 화면:

- 홈 대시보드
- 사주팔자 입력/결과
- 궁합 입력/결과
- 오늘의 운세
- 작명 입력/결과
- 최근 조회 내역
- 즐겨찾기
- 설정

대시보드 구성:

- 상단: 서비스명, 오늘 날짜, 사용자 상태
- 좌측 또는 하단 내비게이션: 사주, 궁합, 오늘운세, 작명, 보관함
- 메인 영역: 기능별 입력 카드와 최근 결과
- 우측 또는 하단 보조 영역: 오늘의 한마디, 저장된 프로필, 주의 문구

### 5.2 사주팔자

입력값:

- 이름 또는 별명
- 성별 또는 선택 안 함
- 생년월일
- 출생 시간
- 출생 시간 모름 옵션
- 양력/음력
- 윤달 여부
- 출생지 또는 시간대

계산/처리:

- 입력 생년월일시를 기준으로 사주 명식 계산
- 연주, 월주, 일주, 시주 산출
- 천간/지지, 오행 분포, 십성, 대략적 균형 산출
- 출생 시간 모름일 경우 시주는 제외하고 해석 신뢰도를 낮게 표시

결과 섹션:

- 요약 한 줄
- 사주 명식 표
- 오행 밸런스
- 성향/기질
- 강점
- 주의하면 좋은 패턴
- 일/커리어 성향
- 인간관계 성향
- 올해의 흐름
- 오늘 활용 팁
- 재미용 안내

### 5.3 궁합

입력값:

- 사람 A: 이름/별명, 성별 선택, 생년월일시, 양력/음력
- 사람 B: 이름/별명, 성별 선택, 생년월일시, 양력/음력
- 관계 유형: 연인, 부부, 썸, 친구, 동료, 가족

결과 섹션:

- 전체 궁합 점수
- 관계 키워드 3개
- 성향 조합
- 끌리는 지점
- 부딪히기 쉬운 지점
- 대화 방식 팁
- 관계 유형별 조언
- 오늘의 궁합 액션
- 재미용 안내

주의:

- 이별, 결혼 성공/실패를 확정하지 않는다.
- 상대방을 조종하거나 단정하는 표현을 금지한다.
- 폭력, 스토킹, 집착을 미화하지 않는다.

### 5.4 오늘의 운세

입력값:

- 저장된 프로필 선택 또는 간단 입력
- 관심 분야: 전체, 연애, 일, 돈, 인간관계, 컨디션

결과 섹션:

- 오늘의 총운
- 분야별 운세
- 행운 키워드
- 행운 색상
- 행운 숫자
- 피하면 좋은 패턴
- 오늘의 짧은 조언

주의:

- 금전운은 투자 조언처럼 보이지 않게 작성한다.
- 건강운은 질병 판단 대신 컨디션 관리 수준으로 제한한다.

### 5.5 작명

입력값:

- 용도: 아기 이름, 개명 아이디어, 예명, 닉네임, 브랜드명
- 성씨
- 성별 이미지 또는 중성적
- 원하는 글자 수
- 선호하는 느낌: 단정한, 밝은, 지적인, 부드러운, 강한, 고전적인, 현대적인
- 피하고 싶은 글자/발음
- 포함하고 싶은 글자/뜻
- 한자 추천 여부

결과 섹션:

- 이름 후보 목록
- 각 이름의 느낌
- 발음/리듬 설명
- 의미 해석
- 한자 후보가 있을 경우 한자와 뜻
- 사주 보완 관점의 가벼운 설명
- 최종 후보 비교표

주의:

- 실제 출생 신고/개명 전에는 전문가 검토가 필요하다는 안내를 포함한다.
- 한자 획수/작명학 계산은 초기 버전에서 "참고 해석"으로 제한한다.

## 6. 제외 범위

1차 버전에서는 아래 기능을 만들지 않는다.

- 관상 이미지 분석
- 손금 이미지 분석
- 결제
- 전문가 상담 매칭
- 커뮤니티
- 관리자 대시보드
- 앱 푸시 알림
- PDF 리포트 유료 다운로드

## 7. 사용자 흐름

### 7.1 첫 방문

1. 사용자가 홈 대시보드에 진입한다.
2. "사주 보기", "궁합 보기", "오늘의 운세", "작명" 중 하나를 선택한다.
3. 필요한 정보를 입력한다.
4. 개인정보 저장 여부를 선택한다.
5. 결과 생성 버튼을 누른다.
6. 로딩 화면에서 짧은 메시지를 보여준다.
7. 결과 화면을 보여주고 저장/공유/다시보기 액션을 제공한다.

### 7.2 재방문

1. 사용자가 홈 대시보드에 진입한다.
2. 최근 조회 결과 또는 저장된 프로필을 선택한다.
3. 오늘의 운세를 즉시 생성하거나 이전 결과를 다시 본다.

## 8. 화면 설계

### 8.1 홈 대시보드

필수 요소:

- 오늘 날짜
- 대표 CTA: 오늘의 운세 보기
- 기능 바로가기 4개: 사주, 궁합, 오늘운세, 작명
- 최근 조회 결과
- 저장된 프로필

### 8.2 입력 화면

필수 요소:

- 단계형 폼 또는 한 화면 폼
- 필수/선택 입력 구분
- 양력/음력 토글
- 출생 시간 모름 체크박스
- 개인정보 저장 체크박스
- 생성 버튼
- 입력 오류 메시지

### 8.3 결과 화면

필수 요소:

- 결과 요약
- 핵심 점수 또는 키워드
- 세부 섹션 카드
- 저장하기
- 다시 생성하기
- 공유용 이미지 만들기
- 재미용/참고용 안내

## 11. AI 사용 전략

### 11.1 역할 분리

- 코드: 날짜 변환, 사주 명식 계산, 오행 점수, 저장, 검증
- AI: 계산된 데이터를 기반으로 쉬운 문장 해석 생성
- UI: AI 결과를 그대로 긴 문장으로 노출하지 않고 섹션별로 정리

### 11.2 AI 출력 형식

AI 응답은 가능하면 JSON Schema를 강제한다.

```ts
type AiFortuneResult = {
  summary: string;
  keywords: string[];
  score?: number;
  sections: {
    title: string;
    body: string;
    bullets?: string[];
  }[];
  lucky?: {
    color?: string;
    number?: number;
    keyword?: string;
  };
  disclaimer: string;
};
```

### 11.3 공통 시스템 프롬프트 원칙

- 한국어로 작성한다.
- 친근하지만 과하게 신비주의적이지 않은 톤을 사용한다.
- 사용자의 미래를 확정하지 않는다.
- 건강, 투자, 법률, 사고, 죽음, 임신, 범죄 관련 예측을 하지 않는다.
- 불안감을 조장하는 표현을 피한다.
- 결과는 재미용이며 자기이해를 돕는 참고 콘텐츠임을 밝힌다.
- 입력값이 부족하면 신뢰도 한계를 표시한다.

## 12. 기술 스택 제안

### 12.1 기본 추천

- Frontend/Fullstack: Next.js
- Language: TypeScript
- Styling: Tailwind CSS
- Component: shadcn/ui 또는 자체 컴포넌트
- Auth: Supabase Auth 또는 Auth.js
- DB: PostgreSQL
- ORM: Prisma 또는 Drizzle
- AI: OpenAI API
- Deployment: Vercel

### 12.2 초기 로컬 개발 대안

빠르게 MVP를 검증하려면 아래 조합으로 시작한다.

- Next.js App Router
- SQLite + Prisma
- 서버 액션 또는 Route Handler
- 로그인 없는 로컬 저장 또는 익명 세션

이후 사용자 계정과 결제가 필요해지면 PostgreSQL/Supabase로 이전한다.

## 13. 라이브러리 검토 항목

사주/궁합/작명에 필요한 원천 데이터, 수집 방법, 캐시 전략, 데이터 버전 관리는 `docs/data-management.md`를 기준으로 관리한다.

사주 명식 계산은 직접 구현 전에 검증 가능한 라이브러리를 조사한다.

검토 기준:

- 양력/음력 변환 지원 여부
- 윤달 지원 여부
- 한국 시간대 기준 처리
- 천간/지지 계산 정확도
- 라이선스
- 테스트 가능성

정확한 라이브러리를 찾기 어렵다면, 1차 버전에서는 계산 로직을 작게 구현하고 테스트 케이스를 충분히 둔다.

## 14. 개인정보와 보안

- 생년월일시는 민감하게 느껴질 수 있으므로 저장 여부를 명확히 묻는다.
- 비로그인 사용자의 정보는 브라우저 로컬 저장 또는 세션 저장으로 제한한다.
- 서버 저장 시 생년월일, 출생시간, 이름/별명은 삭제 가능해야 한다.
- AI API 요청에는 불필요한 개인정보를 보내지 않는다.
- 결과 공유 링크에는 원본 생년월일시를 직접 노출하지 않는다.

## 16. UX 톤앤매너

- 밝고 차분한 분위기
- 너무 무겁거나 공포스러운 점술 느낌은 피한다.
- "나를 알아가는 놀이"에 가깝게 표현한다.
- 결과는 긴 문단보다 카드, 키워드, 짧은 조언 중심으로 제공한다.
- 모바일에서는 입력 단계가 길어지지 않도록 단계형 폼을 고려한다.
