# 사주/운세 대시보드 디자인 문서

## 1. 디자인 목표

이 서비스는 사주팔자, 궁합, 오늘의 운세, 작명을 가볍게 즐기는 웹 대시보드다. 첫 버전은 GitHub Pages에서 운영할 수 있는 정적 웹앱으로 구현한다.

디자인 목표:

- 첫 화면에서 바로 네 가지 서비스를 사용할 수 있어야 한다.
- 전통 점술의 무거운 분위기보다 현대적이고 산뜻한 자기이해 도구처럼 느껴져야 한다.
- 모바일에서도 입력, 결과 확인, 서비스 전환이 쉬워야 한다.
- AI 연동 전에도 목업 결과를 통해 전체 사용 흐름을 확인할 수 있어야 한다.
- 결과는 단정적 예언이 아니라 재미용 참고 콘텐츠임을 명확히 보여준다.

## 2. 톤앤매너

키워드:

- 차분한
- 트렌디한
- 따뜻한
- 신뢰감 있는
- 너무 신비주의적이지 않은

피해야 할 느낌:

- 공포스러운 점술관
- 지나치게 어두운 보라색/남색 위주 화면
- 과도한 금박 장식
- 긴 설명 위주의 랜딩 페이지
- 사용 전 안내만 많은 서비스

## 3. 컬러 시스템

기본 팔레트:

- Background: `#f7f1e8`
- Surface: `#fffaf3`
- Text: `#28231d`
- Muted text: `#756d63`
- Sage: `#657b66`
- Coral: `#d8755b`
- Gold: `#c49a47`
- Ink: `#20262a`
- Border: `rgba(40, 35, 29, 0.12)`

사용 방식:

- 전체 배경은 따뜻한 아이보리 톤을 사용한다.
- 주요 CTA는 코랄과 잉크 색을 조합한다.
- 금색은 점수, 태그, 강조선처럼 작은 면적에만 쓴다.
- 한 가지 색 계열로만 보이지 않도록 세이지, 코랄, 차콜을 함께 사용한다.

## 4. 타이포그래피

권장 폰트:

- 시스템 한글 폰트 우선
- `Pretendard`, `Noto Sans KR`, `Apple SD Gothic Neo`, `Malgun Gothic`

타입 원칙:

- 대시보드 내부 제목은 과도하게 크지 않게 유지한다.
- 결과 카드는 긴 문장보다 짧은 문단과 키워드 중심으로 구성한다.
- 버튼과 탭 텍스트는 모바일에서 줄바꿈이 생기지 않게 한다.

## 5. 레이아웃

### 5.1 전체 구조

- 상단 앱바
- 좌측 서비스 패널
- 중앙 입력/결과 작업 영역
- 우측 오늘의 요약/최근 결과 패널

데스크톱:

- 3컬럼 대시보드
- 좌측 서비스 전환
- 중앙 폼과 결과
- 우측 최근 결과/운영 안내

모바일:

- 상단 앱바
- 서비스 선택은 가로 스크롤 탭
- 입력과 결과는 단일 컬럼
- 보조 패널은 하단으로 이동

### 5.2 첫 화면

랜딩 페이지처럼 긴 설명을 보여주지 않고, 첫 화면부터 바로 서비스를 선택하고 입력할 수 있는 대시보드로 구성한다.

첫 화면 구성:

- 오늘 날짜
- 짧은 서비스 설명
- 네 가지 서비스 탭
- 선택된 서비스 입력 폼
- 샘플 결과 카드
- 최근 확인한 결과

## 6. 네 가지 서비스 UI

### 6.1 사주팔자

입력:

- 이름/별명
- 생년월일
- 출생 시간
- 양력/음력
- 출생 시간 모름

결과:

- 사주 명식 목업
- 오행 밸런스
- 성향 키워드
- 타고난 성향
- 어린 시절과 성장 흐름
- 청년기/직업운
- 금전운
- 사업운
- 관계와 배우자운
- 자식운과 가족운
- 건강/컨디션 운
- 나이대별 흐름
- 조심하면 좋은 시기

주의:

- 건강운은 질병 예측이 아니라 컨디션 관리와 생활 리듬 중심으로 표현한다.
- 나이대별 흐름은 확정 사건이 아니라 전환기/주의 시기/강점이 드러나는 시기로 표현한다.
- 재물운은 투자 조언이 아니라 소비/저축/수익 구조 성향으로 표현한다.

### 6.2 궁합

입력:

- 나의 이름/생년월일
- 상대 이름/생년월일
- 관계 유형

결과:

- 궁합 점수
- 끌리는 지점
- 부딪히기 쉬운 지점
- 대화 팁

### 6.3 오늘의 운세

입력:

- 별명
- 관심 분야

결과:

- 오늘의 총운
- 행운 색상
- 행운 숫자
- 조심할 패턴

### 6.4 작명

입력:

- 성씨
- 용도
- 원하는 느낌
- 글자 수
- 피하고 싶은 글자

결과:

- 이름 후보
- 이름의 느낌
- 발음 리듬
- 의미 seed

## 7. 인터랙션

- 서비스 탭 클릭 시 중앙 폼과 결과가 변경된다.
- 생성 버튼 클릭 시 짧은 로딩 상태 후 결과를 표시한다.
- 결과는 로컬 목업 데이터로 생성한다.
- 최근 결과 목록에 생성한 항목을 추가한다.
- 즐겨찾기 버튼은 UI 상태만 토글한다.

## 8. 안전 문구

모든 결과 영역 하단에 아래 성격의 문구를 표시한다.

- 본 결과는 재미와 자기이해를 위한 참고용 콘텐츠다.
- 건강, 투자, 법률, 관계의 중대한 결정은 전문 정보와 현실 판단을 함께 고려해야 한다.
- 출생 시간이 없거나 입력값이 부족하면 해석 범위가 제한된다.

## 9. 구현 전략

GitHub Pages 운영을 위해 정적 파일만 사용한다.

파일 구조:

```txt
index.html
styles.css
app.js
assets/
  hero-bg.png
docs/
  design.md
```

1차 구현 범위:

- 정적 대시보드 UI
- 네 가지 서비스 탭
- 입력 폼
- 목업 결과 생성
- 최근 결과 상태 관리
- 반응형 레이아웃

2차 구현 범위:

- OpenAI API 연동용 백엔드 또는 서버리스 함수
- DB 저장
- 실제 사주 계산 모듈
- GitHub Pages 외 배포 환경 검토

## 10. GitHub Pages 주의사항

GitHub Pages는 정적 호스팅이므로 API 키를 브라우저에 넣으면 안 된다. AI 연동과 DB 저장이 필요해지는 시점에는 별도 백엔드가 필요하다.

가능한 확장 방식:

- GitHub Pages + 외부 API 서버
- GitHub Pages + Supabase
- Vercel/Netlify로 이전
- Cloudflare Workers를 API 프록시로 사용
